# مراجعة مسار التشغيل والكود — 2026-11-06

## نطاق المراجعة

قراءة ملفات التنفيذ في `src/` و`client/`، خريطة التصادم والأهداف، HTML/CSS والربط بين IDs، package/lock/TypeScript، سكربتات التشغيل، الاختبارات، CI وتعليمات النشر؛ وتشغيل الفحوص التالية. هذه مراجعة تنفيذ وتشغيل، وليست شهادة انعدام أخطاء أو تدقيق اختراق مستقل.

## النتائج المثبتة والإصلاح

| النتيجة | الإجراء |
|---|---|
| `start` يعتمد على `dist` غير الموجود في Git؛ المضيف يحتاج build ناجحًا أولًا | أصبحت هناك نسخة مبنية مسبقًا ومتبعة في `hosting/`، وstart/main يشيران إليها مباشرة |
| أدوات البناء غير متاحة في بيئة المستخدم رغم محاولات التثبيت | أُلغي احتياج المضيف إلى أدوات البناء بالكامل؛ لم نفترض أن نقل dependencies أصلح مثبت Bonto |
| الاعتماد على `prestart` غير موثوق في المسار الظاهر في سجلات المنصة | لا lifecycle hooks في مسار التشغيل الجديد؛ اختُبر تنفيذ Node المباشر دون npm start |
| Three.js كان dependency إنتاج رغم أنه يُضمَّن في bundle | نُقل إلى devDependencies؛ خادم الإنتاج يحتاج ws فقط |
| تقديم الملفات كان نسبيًا إلى cwd؛ المسار قد يختلف عند المنصة | أصبحت مسارات الملفات نسبية إلى موقع module، والاختبار يشغّل من cwd غير متعلق بالمشروع |
| static URLs مع query strings ترجع 404، وhealth لا يكشف غياب الواجهة | تطبيع pathname وتغطية HEAD، وإضافة `/ready` الذي يرجع 503 عند نقص الواجهة |
| إعداد origin بخطأ بسيط قد يمنع WS بدون توضيح مبكر | parser مُختبر يرفض wildcard والمسارات والاعتمادات، ويطبّع slash الأخيرة؛ شرط origin في production محفوظ |
| نشر ناتج مولد في Git قد يؤدي إلى نسخة قديمة | manifest بصمات وفحص CI قبل البناء، وبناء نظيف ثم مقارنة ملفات الناتج |

## التحقق الذي تم فعلًا

- `npm ci --include=dev`: تثبيت نظيف ناجح.
- `npm run typecheck` و`npm run build` و`npm run verify:runtime`: ناجحة.
- اختبارات المصدر: **61 وحدة/تكامل** ناجحة.
- اختبار runtime مستقل: إنشاء مجلد مؤقت، نسخ package/lock وhosting فقط، وتنفيذ **`npm ci --omit=dev`**. تحقق صريح من غياب `src`, `client`, `dist`, TypeScript, esbuild, Three.js عند التشغيل. ثم تشغيل JavaScript مباشرة من cwd آخر وفي NODE_ENV=production.
- حالات runtime تغطي: الواجهة وHEAD وquery strings، /health و/ready، رفض WS origin غريب، إنشاء غرفة وتسجيل لاعبين، معايرة حقيقية بالانتظار 5 ثوانٍ لكل لاعب على البروتوكول (دون ادعاء ميكروفون جهاز حقيقي)، جاهزية وبدء وحركة وتجميد، refresh مع تدوير token وإعادة طلب الميكروفون، readiness عند حذف bundle، ورفض بصمات مصدر/ناتج قديمة. حزمة Node تسجل 5 اختبارات باحتساب الحاوية وأربع حالات فرعية.
- `npm run test:e2e`: **5 حالات Chromium ناجحة**. يستخدم fixture أعداء ثابتين لعزل الواجهة والصوت، ولا يعادل جولة بشرية كاملة.
- `npm run test:load`: 20 غرفة و80 لاعبًا، 30 ثانية افتراضية مسرّعة، p95 = 1.46ms وmax = 9.70ms في تشغيل محلي. لا يشمل الحمل الشبكي الفعلي ولا يثبت سعة Bonto.
- `npm audit`: صفر ثغرات معروفة في الحزم وقت الفحص. `git diff --check`: ناجح.

## ما لم يتم إثباته

- لم أغير ملفات حساب Bonto أو إعداداته، ولم أنشر أو أثبت صلاحية النطاق `dark-signal.bonto.run`.
- نجاح بيئة Node الإنتاجية المعزولة لا يثبت طريقة تثبيت الحزم أو routing أو النوم/الإيقاظ لدى Bonto. لا نعيد تعليمات npm/yarn المرفوضة بدل فحص سجل المضيف.
- الصوت STUN-only حسب القرار، فلا ضمان لعبور كل NAT. اختبار هاتفين على شبكتين، الأداء الرسومي الفعلي، واختبار بشرى لجولة 30 دقيقة ما زال مطلوبًا.
- الغرف في الذاكرة وعملية واحدة؛ إعادة التشغيل تفقدها. لا نشر serverless على Vercel بالشكل الحالي.
- الواجهة blockout لا فن نهائي. مراجعة الكود لا تستبدل إعداد الشات الآخر للفرونت.

راجع [خطوات Bonto الجديدة](BONTO.md) بعد وصول الإصلاح إلى GitHub. لا تعدّل package.json في النسخة القديمة بمحاولات عشوائية أخرى.
