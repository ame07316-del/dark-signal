# تشغيل Bonto بدون TypeScript أو بناء داخل الاستضافة

> تحديث 2026-11-06. هذا إصلاح مُختبر محليًا لمسار التشغيل، **وليس تأكيدًا أن Bonto نشر التطبيق أو أن العنوان العام يعمل**. لا يوجد وصول إداري إلى تطبيق المستخدم في هذه الجلسة.

## ما ثبت من سجلات المستخدم

- ملف الدخول القديم `dist/index.js` لم يكن موجودًا في نسخة Git المستوردة، لأن `dist/` ناتج بناء مستبعد من Git.
- البناء اليدوي توقف عند `tsc: not found`، وحتى `node_modules/.bin/esbuild` لم يوجد بعد محاولات إعادة التثبيت.
- واجهة الحزم منعت `npm ci`، ورفضت `yarn run` وأوصت بـ`npm run`. إضافة الحزم بـ`yarn add` أبلغت بتعديل package.json، دون أن تثبت الصور توافر أدوات البناء.
- السجل أظهر nodemon يشغّل wrapper من المنصة. الاعتماد على `prestart` لم يحل المشكلة؛ لا يجوز افتراض أن المضيف ينفّذ دورة npm lifecycle المعتادة.
- صفحة Bonto ذات 404 ليست استجابة خطأ من خادم اللعبة، ولا تثبت بمفردها سبب عطل ربط النطاق.

## الإصلاح الجديد في المستودع

النسخة القابلة للتشغيل موجودة في **`hosting/` ومشمولة في Git**:

- `hosting/server/*.js`: كود الخادم المترجم إلى JavaScript، بلا اعتماد على tsc أو tsx.
- `hosting/public/index.html`, `style.css`, `app.js`, `assets/`: الواجهة وأصولها المحلية، وThree.js المضمّن مسبقًا في bundle. تتحقق `/ready` من وجود الأصول المسجلة للخدمة.
- `hosting/manifest.json`: بصمات المصدر والناتج لكشف نسيان إعادة البناء.
- سكربت `start` و`main` يشيران إلى `hosting/server/index.js`. لا يوجد `prestart` ولا تحميل حزم أثناء التشغيل.
- الاعتماد الإنتاجي الوحيد هو `ws`؛ Three.js وأدوات البناء والاختبار تظل على جهاز المطور/CI.

وجود هذه الملفات المولَّدة في Git مقصود لتجاوز منصات لا توفر build phase موثوقة. لا تعدّلها باليد؛ عدّل `src/` أو `client/` أو `public/` ثم ابنِ المشروع محليًا قبل رفعه.

## نقل التطبيق الموجود دون إعادة دائرة الأوامر

1. يجب أولًا رفع التحديث المطلوب إلى GitHub. إذا لم يكن مدمجًا في `main`، استورد الفرع الذي يحتويه بدل `main`؛ دمج إصلاح الاستضافة القديم وحده لا يعني أن تحديثات الواجهة الأحدث وصلت للتطبيق.
2. احتفظ بنسخة Bonto القديمة ولا تمسحها؛ تعديلات package.json اليدوية فيها ليست هي نسخة المستودع الجديدة. استخدم تحديث Git إن توفر، أو Import from Git في تطبيق اختبار جديد باسم فرعي متاح؛ لا نفترض أن الحفظ في Arena يحدّث Bonto.
3. افحص وجود `hosting/server/index.js` في شجرة ملفات الاستيراد الجديد. إذا لم يظهر فالنسخة قديمة أو الفرع خاطئ؛ لا تثبّت TypeScript لمحاولة إصلاح نسخة ناقصة.
4. في App Settings اجعل **Start Script = `start`**، وليس أمر shell كاملًا. سكربت package.json الجديد هو:

   ```json
   "start": "node hosting/server/index.js"
   ```

   إذا أبقيت تطبيقًا قديمًا بعد تحديث Git، احذف أي `prestart` محلي مضاف أثناء المحاولات السابقة. لا تحتاج `npm run build` أو `yarn add` على المضيف.
5. من إعدادات البيئة التي تتيحها المنصة اضبط:

   ```text
   NODE_ENV=production
   ALLOWED_ORIGINS=https://العنوان-الفعلي.bonto.run
   ```

   استبدل القيمة بالعنوان الفعلي المختار، وليس نطاق التطبيق القديم إن غيّرت الاسم. لا تضف مسارًا؛ شرطة أخيرة واحدة يقبلها parser ويطبّعها. `PORT` يُقرأ من المضيف، أو الافتراضي 3000 عند عدم توفيره. لا تضف سر المالك؛ الميزة معطّلة ما لم تضبط verifier اختياريًا بنفسك.
6. دع المضيف يثبت اعتماد الإنتاج `ws` بطريقته المعتادة، ثم أعد التشغيل مرة واحدة. لو كانت المنصة عاجزة حتى عن توفير `ws` فذلك عائق منفصل، يظهر كـ`Cannot find package 'ws'`، وليس سببًا لإعادة تثبيت TypeScript.
7. من سجل التشغيل تحقق من `Dark Signal backend listening on port ...`. افتح **Open** في تبويب مستقل حتى لا تقيد iframe أذونات الميكروفون.
8. اختبر `/ready`: يجب أن يرجع `{"status":"ready"}` بكود 200. ثم اختبر الدخول إلى غرفة من متصفحين والمعايرة. `/health` يثبت حياة الخادم فقط؛ `/ready` يتحقق أيضًا من الواجهة.

إذا ظل نطاق Bonto يرجع صفحته الخاصة ذات 404 رغم نجاح سجل الخادم، فهذه ليست مشكلة ملف `dist` القديمة؛ يلزم فحص ربط النطاق/المنفذ لدى المنصة. لم يُختبر ذلك من داخل حساب المستخدم هنا.

## للمطور والشات الذي يعدل الفرونت

```bash
npm ci --include=dev
npm run typecheck
npm run build
npm test
npm run verify:runtime
npm run test:e2e
```

أدرج `hosting/` المحدث مع المصدر وpackage-lock في نفس التغيير. CI يتحقق من البصمات قبل البناء، ثم يعيد البناء ويقارن الناتج؛ فالتعديل في المصدر وحده بدون تحديث نسخة التشغيل يفشل الفحص. لا تنقل Playwright أو Chromium إلى dependencies الإنتاج.
